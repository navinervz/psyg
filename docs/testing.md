# تست‌ها

## چرا vitest یا playwright نیست؟

هیچ‌کدام نصب نشده‌اند. به‌جایش از **تست‌رانر داخلی Node 22** استفاده شده که
هیچ وابستگی جدیدی لازم ندارد و تایپ‌اسکریپت را هم بدون بیلد اجرا می‌کند.

اگر بعداً خواستید مهاجرت کنید، تست‌ها با API استاندارد
(`describe` / `test` / `assert`) نوشته شده‌اند و انتقالشان به vitest تقریباً
کپی‌پیست است.

`tests/hooks.mjs` مسیر `@/...` را مثل tsconfig نگاشت می‌کند و فایل‌های JSON را
قابل ایمپورت می‌کند.

## دستورها

```bash
npm run typecheck    # فقط بررسی تایپ‌ها
npm run test         # typecheck + تست‌های واحد و ایستا
npm run test:unit    # فقط تست‌های واحد
npm run test:e2e     # نیازمند build قبلی — سرور را بالا می‌آورد و می‌بندد
npm run test:all     # همه‌ی موارد بالا پشت سر هم
```

## چه چیزی تست می‌شود؟

### `tests/unit/format.test.ts` — ۱۴ تست
تبدیل ارقام فارسی، قالب قیمت، درصد تغییر، زمان نسبی.
شامل حالت‌های مرزی مثل تقسیم بر صفر در `priceDelta`.

### `tests/unit/data.test.ts` — ۲۰ تست
یکپارچگی کاتالوگ:

- یکتا بودن `slug` و `id`
- همه‌ی محصولات فقط از دیجی‌کالا (تصمیم فاز اول)
- معتبر بودن دسته‌بندی و فروشگاه هر محصول
- لینک مبدأ همه‌ی محصولات به `digikala.com/product/`
- هر محصول دقیقاً ۳۰ نقطه تاریخچه دارد
- آخرین نقطه‌ی تاریخچه دقیقاً برابر `currentPrice` است
- تاریخ‌ها صعودی و بدون تکرار
- درستی سلکتورها (`topDeals` واقعاً مرتب است، `relatedProducts` خودِ محصول
  را برنمی‌گرداند و…)
- هر هشدار به محصول موجود اشاره می‌کند

### `tests/unit/analysis.test.ts` — ۵ تست
منطق «الان بخرم یا صبر کنم»: کف بازه، سقف بازه، وسط، قیمت ثابت
(تقسیم بر صفر)، و اینکه `position` روی کل کاتالوگ همیشه بین ۰ و ۱۰۰ می‌ماند.

### `tests/unit/routes.test.ts` — ۱۶ تست
**این مهم‌ترین بخش است.** درخت `src/app` را می‌خواند، الگوی همه‌ی روت‌ها را
استخراج می‌کند، بعد همه‌ی `href`های سورس را بیرون می‌کشد و چک می‌کند هرکدام
به یک صفحه‌ی واقعی می‌رسند. اگر لینکی به صفحه‌ی ناموجود اشاره کند، تست قرمز
می‌شود.

همچنین:

- سه **کنترل منفی** که ثابت می‌کنند خود تست الکی سبز نمی‌شود
- هر محصول/دسته/مقاله صفحه‌ی قابل تولید دارد و `slug`ش برای URL امن است
- دکمه‌ی خرید از `/go/` عبور می‌کند و `rel="nofollow sponsored"` دارد
- هیچ‌جای سورس مستقیم به دیجی‌کالا لینک نمی‌دهد
- هر فایلی که هوک React دارد `"use client"` هم دارد
- هیچ کامپوننتی مستقیم از `@/data/*.json` نمی‌خواند

### `tests/unit/derived.test.ts` — ۱۷ تست
جلوی برگشتن یک باگ واقعی را می‌گیرد: قبلاً هشدارها درصد هاردکد داشتند که
با داده‌ی محصول نمی‌خواند (کاربر روی «۱۸٪ کمتر» کلیک می‌کرد و در صفحه‌ی
محصول «۴٪» می‌دید). حالا همه‌چیز از `products` مشتق می‌شود و این تست‌ها
تضمین می‌کنند عدد هشدار دقیقاً همان عددی است که در صفحه‌ی محصول دیده
می‌شود. سطح کاربر هم اینجا تست می‌شود.

### `tests/unit/articles.test.ts` — ۱۰ تست
مجله مهم‌ترین بخش برای تایید رسانه است، پس این تست‌ها نمی‌گذارند دوباره
به حالت «عنوان بدون متن» برگردد:

- حداقل چهار مقاله با حداقل ۳۰۰ کلمه
- هر مقاله تیتر میانی و چند پاراگراف دارد (ساختار، نه یک تکه متن)
- هیچ متن جای‌نگهداری (lorem, TODO, «هنوز نوشته نشده») باقی نمانده
- جدول‌ها ستون‌هایشان با سرستون می‌خواند
- `readMinutes` در JSON ذخیره نشده و از خود متن حساب می‌شود

### `tests/e2e/crawl.test.ts` — نیازمند سرور
روی بیلد پروداکشن اجرا می‌شود:

- همه‌ی روت‌ها (بیش از ۵۰ آدرس) وضعیت ۲۰۰ می‌دهند
- صفحه‌های کلیدی خزیده می‌شوند و **همه‌ی لینک‌های داخلی‌شان** تست می‌شود
- صفحه‌ی محصول عنوان، دکمه خرید، `rel` درست و JSON-LD دارد
- `/go/[id]` واقعاً به دیجی‌کالا ریدایرکت می‌کند و شناسه‌ی نامعتبر به
  `/deals` برمی‌گردد
- API خبرنامه: ایمیل درست ۲۰۰، ایمیل غلط ۴۲۲، JSON خراب ۴۰۰ (نه ۵۰۰)
- sitemap همه‌ی محصولات و دسته‌ها را دارد، robots مسیرهای حساس را می‌بندد
- افشای کمیسیون در صفحه‌های اصلی وجود دارد (شرط تایید رسانه)
- هر صفحه دقیقاً یک `h1` دارد و دکمه‌های آیکونی `aria-label` دارند

## اجرای e2e

```bash
npm run build
npm run test:e2e
```

`scripts/run-e2e.mjs` سرور را بالا می‌آورد، منتظر آماده شدنش می‌ماند،
تست‌ها را اجرا می‌کند و در پایان — حتی اگر تست‌ها شکست بخورند — سرور را
می‌بندد.

## چیزهایی که در لاگ می‌بینید و مشکل نیستند

### `Error: Internal: NoFallbackError`

هر بار که آدرس محصول/دسته/مقاله‌ی ناموجودی درخواست شود، Next این خط را در
لاگ سرور می‌نویسد. **باگ نیست.** این سیگنال داخلی خود Next است برای
«این پارامتر در `generateStaticParams` نبود و `dynamicParams = false` است،
پس ۴۰۴ بده».

پاسخ نهایی درست است — تست‌های `۴۰۴ برای بقیه‌ی مسیرهای پویا` دقیقاً همین را
بررسی می‌کنند. فقط لاگش پرسروصداست.

اگر بعداً در پروداکشن این لاگ اذیت کرد، وقتی به فاز ۲ رسیدید و محصولات از
دیتابیس آمدند، `dynamicParams` را `true` می‌کنید و `revalidate` می‌گذارید؛
آن‌وقت این پیام هم می‌رود.

**ولی هرگز صرفاً برای تمیز شدن لاگ آن را `true` نکنید** — قبلاً همین باعث
می‌شد آدرس‌های ناموجود پاسخ ۲۰۰ بدهند و گوگل بی‌نهایت صفحه‌ی بی‌محتوا
ایندکس کند.

### `MODULE_TYPELESS_PACKAGE_JSON`

خاموش شده. علتش این بود که فایل‌های `.ts` زیر `src/` در پکیجی هستند که
`type: "module"` ندارد. به `package.json` اصلی دست نزدیم تا پیکربندی Next
دست‌نخورده بماند و به‌جایش هشدار را با
`--disable-warning=MODULE_TYPELESS_PACKAGE_JSON` غیرفعال کردیم.

## بازتولید داده‌ها

```bash
npm run data:generate
```

`scripts/generate-products.mjs` کاتالوگ را با تاریخچه‌ی ۳۰ روزه می‌سازد. از
یک PRNG با seed ثابت استفاده می‌کند، پس خروجی همیشه یکسان است و تست‌ها
پایدار می‌مانند.
