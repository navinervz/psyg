## ⚡ وضعیت زنده — آخرین به‌روزرسانی

**سایت روی اینترنت است:** https://psygstore.shop

### زیرساخت فعلی

| مورد | وضعیت |
|---|---|
| سرور | `2.58.172.224` — اوبونتو ۲۲.۰۴، ۸ گیگ رم، SSH روی پورت **۹۰۱۱** |
| مسیر پروژه | `/opt/psyg` |
| n8n | `/opt/n8n` — روی `n8n.psygstore.shop` |
| روش انتشار | **Cloudflare Tunnel** به نام `psyg-server` (کانتینر `cf-tunnel-new`) |
| فایروال | فقط پورت ۹۰۱۱ باز است — نه ۸۰، نه ۴۴۳، نه ۵۶۷۸ |
| SSL | توسط کلادفلر؛ هیچ گواهی‌ای روی سرور نیست و لازم هم نیست |
| DNS | سه رکورد از نوع Tunnel: `@`، `www`، `n8n` |

### چرا Nginx و certbot نصب نشد

سرور از قبل Cloudflare Tunnel داشت. تانل یک اتصال **خروجی** به کلادفلر
باز می‌کند، پس نیازی به باز کردن پورت، گرفتن گواهی و تمدید آن نیست و IP
سرور هم پنهان می‌ماند. کانفیگ‌های Nginx در `deploy/nginx/` باقی مانده‌اند
برای روزی که بدون تانل دیپلوی شود.

**تانل قبلی از نوع Quick Tunnel بود** (`tunnel --url ...`) که آدرسش با هر
ری‌استارت عوض می‌شود. با تانل نام‌دار جایگزین شد — که هم سایت را حل کرد
هم n8n را از شکنندگی نجات داد.

### دستورهای روزمره

```bash
# به‌روزرسانی سایت (بعد از scp کردن بسته)
cd /opt/psyg && unzip -q -o /opt/psyg-deploy.zip && docker compose up -d --build

# بررسی سلامت MCP (توکن چاپ نمی‌کند)
bash /opt/psyg/scripts/check-mcp.sh

# تعویض توکن MCP
cd /opt/psyg && NEW=$(openssl rand -hex 32) \
  && sed -i "s|^PSYG_MCP_TOKEN=.*|PSYG_MCP_TOKEN=$NEW|" .env \
  && unset NEW && docker compose up -d
```

ساخت بسته روی ویندوز:
```powershell
cd C:\Users\NAVIX\OneDrive\Desktop\psyg
powershell -ExecutionPolicy Bypass -File scripts\package-for-server.ps1
scp -P 9011 "C:\Users\NAVIX\OneDrive\Desktop\psyg-deploy.zip" root@2.58.172.224:/opt/
```

## ۲. مسیری که طی کردیم

### گام اول — استخراج دیزاین

از فایل `psyg.jpg` نوزده کامپوننت استخراج شد. یک تفاوت عمدی با عکس:
بخش Premium حذف شد و ویجت «خبرم کن» جایش نشست.

**تصمیم چیدمان.** فایل رفرنس چیدمان LTR داشت (لوگو چپ، سایدبار راست، کارت
۰۱ چپ) ولی متن‌ها فارسی بودند. من اول RTL کامل زدم که آینه‌ی عکس شد. وقتی
پرسیدم، گفتی مو به مو مطابق عکس باشد. راه‌حل: `<html dir="rtl">` برای
درست رندر شدن متن و اعداد فارسی، و `dir="ltr"` روی کانتینرهای ساختاری.

### گام دوم — استک

| لایه | انتخاب | دلیل |
|---|---|---|
| فریم‌ورک | Next.js 15 + TypeScript | SSR/ISR برای سئو که در فاز ۲ لازم می‌شود |
| استایل | Tailwind v4 | سرعت، پشتیبانی بومی از RTL |
| انیمیشن | GSAP + ScrollTrigger + Lenis | کنترل دقیق تایم‌لاین اسکرول |
| استیت | Zustand + localStorage | فاز اول بک‌اند ندارد |

دو تصمیم که بعداً ارزششان معلوم شد:

**Google Fonts حذف شد.** هم بیلد را به سرویس بیرونی گره می‌زد، هم برای
مخاطب ایرانی قابل اتکا نبود. `@font-face` خودمان تعریف شد و فایل‌ها از
`public/fonts` سرو می‌شوند.

**توکن رنگ پس‌زمینه `night` نام گرفت نه `base`،** چون Tailwind خودش
`text-base` را برای اندازه‌ی فونت رزرو کرده و تداخل می‌شد.

### گام سوم — ساخت کامل سایت

نوزده روت: صفحه اصلی، فرصت‌ها، محصول، دسته‌بندی، فروشگاه‌ها، مجله و
مقالات، درباره، تماس، حریم خصوصی، جستجو، پنج صفحه‌ی حساب کاربری، مسیر
خروج افیلیت، API خبرنامه، اندپوینت MCP، sitemap و robots.

وقتی گفتی «خیلی از قسمت‌ها فقط وجود دارن و با کلیک اتفاقی نمی‌افته»، همه‌ی
دکمه‌های مرده زنده شدند: علاقه‌مندی و پیگیری واقعاً در localStorage ذخیره
می‌شوند و در صفحه‌های حساب دیده می‌شوند، زنگ اعلان و صندوق پیام دراپ‌داون
واقعی دارند، چیپ‌های دسته‌بندی به صفحه‌ی دسته می‌روند.

### گام چهارم — سیستم تست

رجیستری npm در محیط من بسته بود، پس نه vitest نصب می‌شد نه playwright.
به‌جایش از تست‌رانر داخلی Node 22 استفاده شد — بدون هیچ وابستگی جدید،
با اجرای مستقیم TypeScript.

مهم‌ترین تست `routes.test.ts` است: درخت `src/app` را می‌خواند، همه‌ی
`href`های سورس را بیرون می‌کشد و تطبیق می‌دهد. سه کنترل منفی هم دارد که
ثابت کنند خودش الکی سبز نمی‌شود.

### گام پنجم — دیپلوی و MCP

کانفیگ داکر و Nginx، و یک اندپوینت MCP که با آن می‌شود هوش مصنوعی را به
سایت زنده وصل کرد.

## ۳. باگ‌هایی که تست‌ها گرفتند

این مهم‌ترین بخش گزارش است، چون نشان می‌دهد تست‌ها تزئینی نبودند.

### ۳.۱ آدرس ناموجود پاسخ ۲۰۰ می‌داد

صفحه‌ی محصول `generateStaticParams` داشت ولی `dynamicParams` پیش‌فرض
`true` بود، پس Next برای هر slug ناشناخته صفحه را در لحظه می‌ساخت.

**چرا مهم بود:** گوگل می‌توانست بی‌نهایت آدرس بی‌محتوا با پاسخ ۲۰۰ ایندکس
کند — دقیقاً چیزی که کیفیت دامنه را خراب می‌کند و می‌تواند دلیل رد شدن
رسانه شود.

**رفع:** `dynamicParams = false` روی هر سه مسیر پویا.

### ۳.۲ هشدارها عدد دروغ نشان می‌دادند

سایدبار می‌گفت «ASUS TUF ۱۸٪ کمتر» ولی داده‌ی خود محصول ۴.۴٪ بود.

**چرا مهم بود:** برای سایتی که کل ارزشش دقت قیمت است، این یعنی بی‌اعتباری.

**رفع:** هشدارها و پیشنهادها دیگر ذخیره نمی‌شوند؛ از روی `products`
محاسبه می‌شوند.

### ۳.۳ پروفایل ساختگی بود

به هر بازدیدکننده «تریدر حرفه‌ای، ۱۵۰۰ امتیاز» نشان می‌داد.

**چرا مهم بود:** عددی که پشتوانه ندارد به کاربر می‌گوید بقیه‌ی اعداد سایت
هم ممکن است ساختگی باشند.

**رفع:** امتیاز از فعالیت واقعی می‌آید؛ سطح از «تازه‌وارد» شروع می‌شود.

### ۳.۴ زمان مطالعه اغراق‌شده بود

مقاله‌ی ۳۲۰ کلمه‌ای ادعای «۸ دقیقه مطالعه» داشت. تستی که خودم نوشتم
گرفتش.

**رفع:** از روی متن حساب می‌شود و در JSON ذخیره نمی‌شود.

### ۳.۵ نود و هفت کیلوبایت JSON روی هر صفحه

`HeaderActions` که در همه‌ی صفحه‌ها رندر می‌شود از `lib/data` می‌خواند، و
آن ماژول کاتالوگ را ایمپورت می‌کند.

**رفع:** لایه‌ی داده دو تکه شد — `lib/reference.ts` سبک برای کلاینت،
`lib/data.ts` سنگین فقط برای سرور.

### ۳.۶ نقطه‌کور خودِ تست

بعد از رفع بالا صفحه‌ی اصلی همچنان سنگین ماند. علتش این بود که **مرز
کلاینت در Next زنجیره‌ای است**: `Sidebar` که `"use client"` داشت،
`RecentAlertsCard` سروری را ایمپورت می‌کرد و همان کافی بود.

تست اولیه‌ام فقط فایل‌هایی را می‌دید که خودشان `"use client"` دارند.

**رفع:** `Sidebar` سروری شد، انیمیشن به `RevealColumn` منتقل شد، و تست
بازنویسی شد تا کل گراف ایمپورت را دنبال کند.

**نتیجه:** صفحه اصلی ۲۱۸ → ۲۰۴، صفحات داخلی ۱۸۰ → ۱۶۶ کیلوبایت.

### ۳.۷ خطای اجرای تست روی ویندوز

`spawn npx ENOENT` — روی ویندوز `npx` فایل `.cmd` است و `spawn` بدون shell
پیدایش نمی‌کند.

**رفع:** اجرای مستقیم CLI نکست با همان node جاری.

## ۴. تصمیم‌های معماری ماندگار

### هیچ عددی دو بار ذخیره نمی‌شود

درصد تغییر قیمت، هشدارها، پیشنهادها، سطح کاربر و زمان مطالعه همگی محاسبه
می‌شوند. منطق در `src/lib/derived.ts`.

### دکمه خرید از `/go/[id]` رد می‌شود

چهار دلیل: لینک افیلیت در یک تابع ساخته می‌شود، کلیک‌ها قابل شمارش‌اند،
تغییر ساختار لینک فقط یک فایل را عوض می‌کند، و `rel="nofollow sponsored"`
الزام گوگل برای لینک‌های کمیسیونی است.

### آداپتور فروشگاه

`StoreAdapter` قرارداد واحد همه‌ی فروشگاه‌هاست. برای افزودن فروشگاه جدید
فقط یک فایل ساخته و ثبت می‌شود.

**نکته درباره‌ی دیجی‌کالا:** برنامه‌ی همکاری در فروششان لینک‌محور است و
فید عمومی محصول ندارد. به همین دلیل تولید لینک افیلیت از جمع‌آوری قیمت
جدا نگه داشته شده.

### افشای شفاف کمیسیون

`AffiliateNotice` در صفحه‌های اصلی هست. هم شرط پذیرش در برنامه‌های همکاری
است، هم توصیه‌ی صریح گوگل. تست e2e وجودش را بررسی می‌کند.

## ۵. امنیت

### MCP فقط-خواندنی است

خواسته‌ات این بود که دسترسی به همه چیز داشته باشم. اندپوینتی که بتواند
فایل عوض کند یا دستور اجرا کند، یک در پشتی روی سرور پروداکشن است. توکنش
دیر یا زود بیرون می‌رود — تاریخچه‌ی چت، اسکرین‌شات، لاگ سرویس واسط. از آن
لحظه هرکس آن را دارد می‌تواند لینک‌های افیلیت را به نام خودش بزند و
کمیسیونت را بردارد.

پس MCP **دید** می‌دهد نه دست. تستی هم هست که اگر کسی ابزار نوشتنی اضافه
کند، قرمز شود.

### تدابیر پیاده‌شده

| مورد | توضیح |
|---|---|
| احراز هویت fail closed | بدون توکن، اندپوینت اصلاً پاسخ نمی‌دهد |
| حداقل ۳۲ کاراکتر توکن | توکن کوتاه قابل حدس است |
| مقایسه‌ی timing-safe | جلوگیری از حدس کاراکتر‌به‌کاراکتر توکن |
| هدرهای امنیتی | X-Frame-Options، nosniff، Referrer-Policy، HSTS |
| poweredByHeader: false | نسخه‌ی فریم‌ورک لو نرود |
| کاربر غیرروت در کانتینر | محدود کردن دامنه‌ی آسیب |
| اپ روی 127.0.0.1 | دسترسی مستقیم از بیرون ممکن نیست |
| محدودیت نرخ | در `src/middleware.ts` — مستقل از پراکسی |
| عدم افشای داده | ایمیل مشترکین و مقدار متغیرها هرگز برنمی‌گردد |

> **تصحیح (مرداد ۱۴۰۵).** دو مورد از این جدول قبلاً فقط در
> `deploy/nginx/psyg.conf` پیاده شده بودند — محدودیت نرخ و HSTS. چون سایت
> با Cloudflare Tunnel منتشر می‌شود و Nginx در مسیر درخواست نیست، هیچ‌کدام
> در پروداکشن اعمال نمی‌شدند. هر دو به خود اپ منتقل شدند.
> جزئیات: `docs/audit-2026-08.md`

### ابزار `security_audit`

سایت زنده را بررسی می‌کند و برای هر یافته سه چیز می‌گوید: چه چیزی غلط
است، چرا مهم است، چطور درست می‌شود.
